★★★Claude CodeのVS Code拡張にバックドア、Cursor Marketplace配布版
Backdoor in Claude Code for VS Code extension on the Cursor Marketplace
Hacker News
Phorionは、Cursor Marketplaceで配布されていたClaude Code for VS Code拡張のバンドルにバックドアを検出したと公表した。macOS・Linux・Windowsで永続的なSSHバックドアを仕込み、macOSではSSH設定の書き換えと永続化を試みる。影響を受ける版として2.1.313を挙げ、利用環境の点検とインシデント対応を求めている。正規配布物が改ざんされたのか依存側が侵害されたのかは、この記事では特定されていない。
★★★無印良品、MUJIアプリで最大2726万件の情報が流出の可能性
無印良品、「MUJIアプリ」の利用者情報最大約2726万件が不正アクセスにより流出の可能性
はてなブックマーク
良品計画は10月30日、MUJIアプリで利用者情報の一部が外部に流出した可能性があると公表した。対象は最大2726万件（退会者を含む）で、メールアドレス・生年月日・性別。クレジットカード情報、氏名、住所、電話番号は含まれないとしている。原因や経緯は明らかにされておらず、不正アクセスを検知して遮断と修正を行ったという。アプリとネットストアは正常に利用できる状態。
関連: 10/30号の国内インシデント
★★★AzureのAPI Connectionsに5件のクロステナント昇格、報奨金20万ドル
Azure's Weakest Link – Five Full Cross-Tenant Compromises
Hacker News
Binary Securityは、Azure Logic AppsのAPI Connectionsに5件の重大な権限昇格脆弱性を報告した。テナントをまたいでKey VaultやAzure SQLなど接続先のサービスに到達でき、悪用を止めているのは入力検証の層だけだったと指摘する。報奨金は合計20万ドルで、報告した脆弱性はすべて修正済みだとしている。

AI・LLM ★★

★★★AIはSREを代替せず「脱スキル化」する、SigNozの記事
AI isn't replacing SREs, it's deskilling them
Hacker News
SigNozの記事は、AIがインシデント対応の大部分を担うようになると、残りの難しい判断を人が下せなくなる「脱スキル化」を論じている。SREが将来のソフトウェアエンジニアリングになるという予測と、AIがSREも含めて職を奪うという予測の、どちらでもない位置づけを示す。監視や対応を自動化するほど、人が学ぶ機会をどう残すかが論点になる。

★★★文章のAIっぽさを抑えるプロンプト、癖を具体的に潰す
文章のAIっぽさを抑えるプロンプト
はてなブックマーク

★★★LinuxカーネルCVE-2026-98432、カーリルが影響と対応を公開
Linuxカーネルの重大な脆弱性（CVE-2026-98432）によるカーリルへの影響について
はてなブックマーク
2026年10月15日にLinuxカーネルのネットワーク処理の脆弱性CVE-2026-98432が公表され、修正版も公開された。細工したパケットでサーバーを停止させられ、条件によっては認証なしでリモートからコードを実行されるおそれがある。カーリルは自社への影響と対応をブログで説明している。
関連: piyolog のまとめ
★★★個人情報を自社DBに持たない設計はどこまでできるか
個人情報を自社のDBに持たない設計は、どこまでできるのか
はてなブックマーク
漏えいのニュースが増える中で、そもそも自社のデータベースに個人情報を持たない設計がどこまで成立するかを、セキュリティ専門ではないエンジニアの視点で整理している。何を外部に預け、何を自社に残すと漏えい時の影響が変わるのかを、実装の選択肢とあわせて論じている。
★★★GitHub Actionsのlockfile対応、利用者と提供者の両面から
GitHub Actions の lockfile対応 - 利用者と提供者両方の観点から
はてなブックマーク
GitHub Actionsのlockfile対応を、使う側とアクションを提供する側の両方から整理している。利用者側は使わない理由がない一方、カスタムアクションや再利用可能ワークフローの提供者向け仕様はまだ議論中だとして、現状を理解したうえで提供方法を見直すよう促している。
関連: 10/30号: actions.lock の記事
★★★NoSQLのスキーマ変更は「読むときに受け止める」
NoSQLのスキーマ変更は読むときに受け止めよう
Zenn
DynamoDB・Firestore・MongoDBのようなスキーマレスDBでも、保存済みの古い形のデータが問題になる。データにスキーマのバージョンを持たせ、読むときに古い版を最新へ変換する方法を、TypeScriptとZodのdiscriminatedUnionを使った例で示す。データの書き換えとコードのデプロイは同時に終わらないため、新旧が混ざる時間を前提に設計する。
★★★WASIの代わりにLinuxシステムコールを使う「WALI」の提案
WASIじゃない、もう一つのインターフェース「WALI」という提案
Zenn
wasmで既存のCLIを動かすとき、WASIにはfork・シグナル・mmapが無く、ソースに #ifdef __wasi__ を足す作業が発生する。WALI（WebAssembly Linux Interface）は、WASIのような新しいAPIを作るのではなく、Linuxのシステムコールをそのまま使う方向の研究で、その考え方を紹介している。
